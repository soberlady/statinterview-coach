# 练习可靠性与持续训练优化

日期：2026-10-03。范围：本地代码与本地验证；未发布到远程环境。

## 优化方向

继续服务个人面试前训练，优先保证回答不会因网络和刷新而白写、训练可以合理继续、旧记录有稳定的解释依据。保留七题诊断的 2+2+3 结构、最多两次追问、评分可靠性门控，以及两题有提示练习加一题无提示复测。没有扩充题目数量或引入新的评分模型。

## 已落实

1. **提交与结束恢复。** 相同会话、序号、题号和回答的重试识别为只读重放，允许在暂停、结束确认、已完成状态返回已有结果。重放补齐评分和当前能力状态，既不重新调用评分，也不重复写入。不同回答的冲突及结束后的新写入继续拒绝。最后一题保存后即进入独立确认界面；确认失败时可以重试或查看已保存报告，无需重复作答。
2. **本机草稿。** 按会话保存题号、文本和保存时间；恢复时核对服务端当前题，题号不同、格式损坏或超过 24 小时的记录不恢复。提交确认后清除，可手动清除。浏览器存储被禁用或已满时不阻断输入，显示保存不可用提示。草稿只保存在当前浏览器，不能代替服务端提交记录；过期清理由访问时触发。
3. **连续训练。** 按可靠薄弱证据、证据缺口、岗位权重和不确定性排序多个候选主题。优先主题无法组成完整题组时，尝试下一主题并显示原因。每个计划仍须同主题、三道不同未答题，复测题族避开历史和本轮两道练习。穷尽候选后才返回没有可用计划；既有持久化计划不重排。
4. **题库版本。** 原 24 题与当前 48 题均使用不可变快照。新会话保存 `policyConfig.questionBankVersion`；旧 v2 配置解析到原 24 题，未带题库版本的已有 v3 配置解析到首次 v3 快照。选题、提交评分、训练和报告回放读取对应版本。无需新增数据库列或迁移。
5. **持续回归。** 草稿、题库版本、连续训练和语音处理测试进入总测试入口；Playwright 固定为开发依赖。浏览器恢复测试与本地 D1 端到端测试一起运行，CI 安装 Chromium。测试使用合成演示和本地模拟评分服务，不依赖真实模型或麦克风。

## 验证

入口：`npm run verify:code`，包含内容、lint、typecheck、Python 测试、生产构建、网页与 TypeScript 测试、本地 D1 与浏览器端到端测试、实验产物重建。

- 题库：48 道主问题、97 条独立量表追问通过校验。
- Python：103 项通过，1 项可选 LiveKit 运行时检查因未安装语音依赖跳过。
- 配置与页面源码检查：14 项通过；TypeScript：83 项通过。
- 浏览器：草稿刷新/暂停恢复、清除、响应丢失后的重试、最终提交重试、完成状态失败恢复、报告进入专项训练、复测刷新后继续隐藏提示，以及 390/320 像素布局与键盘跳转。
- D1：七题正常诊断、三题训练和引导演示可回放；普通及最终回答重试不增加评分调用或改变保存状态；暂停和已完成时重放保持状态不变，已完成后的新写入仍被拒绝。
- 连续训练：4 个岗位 × 3 档合成分数均可完成第一轮后生成另一完整计划；所有题目用尽后仍正确停止。该结果验证程序边界，不代表真人训练效果。
- 快照：固定内容哈希；修改未发布编辑稿不改变旧会话选题与回放。当前编辑稿必须与当前发布快照一致。
