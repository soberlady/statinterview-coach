# 当前代码审查与后续优化（2026-10-03）

范围：基于当前工作区，检查会话 API、文本作答与恢复、训练推荐、题库版本、评分边界和测试入口。本轮没有修改产品代码；复现脚本及结果放在忽略目录 `.tmp`，本地数据库增加了明确标记的合成演示会话。没有调用真实模型、语音服务或操作远程数据。

## 优先修复

### 1. 最后一题的重试和结束失败恢复不完整

位置：`app/api/interviews/[id]/turns/route.ts:130`、`:140`；`app/components/InterviewRoom.tsx:476`、`:481`。

- 提交接口先检查会话是否接受新回答，再检查相同题号、序号和回答的重复请求。最后一题成功保存后状态为 `FINALIZING`，原样重试返回 `409 INTERVIEW_NOT_ACTIVE`。因此“服务器保存成功，但客户端未收到响应”的情况无法通过同一次提交重试恢复。
- 中间题重复提交返回成功，但缺少首次响应中的顶层 `evaluation`；前端按这个字段更新反馈，重试后可能保留上一题反馈。
- 模拟最后一次回答保存成功、随后完成状态更新返回 503：数据库已有七题，界面显示 7/7，却保留最后一题和空输入框，只有提交回答与暂停入口。刷新可以恢复，但页面没有明确引导。

建议：把完全相同的已保存请求识别为只读重放，再对真正的新写入校验状态；重放保持原有响应字段。将“回答已保存、等待结束确认”作为独立的前端恢复状态，提供重试完成、重新同步或查看报告的入口，避免要求再次作答。测试覆盖响应丢失、最终状态更新失败以及重复请求不重复评分/更新后验。

### 2. 未提交的回答没有草稿恢复

位置：`app/components/InterviewRoom.tsx:121`、`:514`。

回答只存在组件状态中。本地 Chrome 实测：输入 32 字未提交回答，刷新后长度为 0。当前检查点保存的是已提交轮次，暂停操作也不会保存文本草稿。

建议：按会话和题号保存本地草稿，恢复时必须与服务端当前题核对，避免串题；提交确认后清除，并设置有效期及清除入口。界面区分“本机草稿已保存”和“本轮回答已提交”。补充刷新、暂停返回、题目切换和提交响应丢失的回归检查。

## 随后优化

### 3. 连续训练缺少候选主题回退

位置：`app/lib/practice-plan.ts:85`、`:95`、`:97`。

算法只尝试最高优先级的一个主题。该主题不能组成“两道练习 + 一道未见复测”时，直接返回空计划，不再尝试其他合适主题。这符合当前保守设计，但容易中断个人持续练习。

用已有合成会话工具验证 4 类岗位 × 3 档注入分数：第一次均可创建训练；低、中分的 8 个场景完成三题后，下一计划为空，而其他主题仍有至少三道未答非锚点题。这是合成边界复现，不能解释为真实用户失败率，也不意味着其他主题必然适合替代原主题。

建议：先排序多个“需要练习且有完整题组”的候选主题；当前薄弱主题耗尽时明确解释，再允许转向次优主题或补充诊断。保留同主题、复测独立和排重要求，不用无关题目勉强凑数。新增连续两轮以上的测试。

### 4. 历史策略被冻结，但历史题库读取仍指向当前内容

位置：`app/lib/question-bank.ts:1`、`:49`；`app/lib/agent-policy-v2.ts:1`；`app/lib/decision-audit.ts:109`。

`listLegacyQuestions()` 从当前题库按编号筛出原 24 题；历史回放也通过同一个当前题库查询题目。现有旧题内容保持不变，所以本次没有观察到历史回放失败。但将来调整旧题难度、标签、评分量表或预计时长时，冻结策略仍可能产生不同选题或后验。

建议：会话同时固定策略版本与题库版本，评分和回放读取对应的不可变内容；旧会话使用已有旧题库快照。增加“当前题库更新，旧会话结果不变”的回归检查。该优化对项目所强调的可重放能力尤其重要。

### 5. 关键浏览器边界未进入持续验证

位置：`package.json:9`、`:15`、`:32`；`tests/rendered-html.test.mjs:9`；`.github/workflows/ci.yml`。

- `test:voice-processing` 有独立入口，但不在 `npm test` 或 `verify:code` 的调用链中。
- `rendered-html.test.mjs` 主要读取源码并匹配文案，不能验证实际点击、刷新和错误恢复。
- 前轮 UI 验收脚本位于 `.tmp`，没有成为仓库内持续运行的浏览器回归测试。

建议：将语音处理测试纳入总入口；保留少量稳定的浏览器关键路径：草稿恢复、最后一题结束失败恢复、专项训练提示边界、窄屏导航。沿用本地合成演示或模拟评分，避免持续验证依赖真实模型。
