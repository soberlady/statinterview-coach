# 证据报告设计与验证边界

核对日期：2026-10-19。本文件说明当前实现合同，不代表线上部署或真人评分验收已经完成。

## 输入与职责

报告读取已保存的原始回答、评分记录及会话固定的题库版本，不重新调用评分模型，也不为旧记录补造引用或评阅说明。报告将“已观察到的错误”和“没有足够证据”分开，输出可启动的训练方向。

| 模块 | 职责 |
| --- | --- |
| [report-insights.ts](../app/lib/report-insights.ts) | 可靠证据、逐项状态、追问关联、训练优先级与复测对照 |
| [DiagnosticReportContent.tsx](../app/components/DiagnosticReportContent.tsx) | 展示原话、反馈、待确认原因及参考量表 |
| [practice-plan.ts](../app/lib/practice-plan.ts) | 服务端生成持久化题组、同主题与题族排除 |
| [decision-audit.ts](../app/lib/decision-audit.ts) | 从保存评分重放选题与后验，不复评语义正确性 |

## 什么可以成为能力证据

普通报告的可靠证据要求已完成、非空回答，`RUBRIC_DOUBLE_PASS`、`ACCEPT` 和 HIGH/MEDIUM 可靠性。`DEMO_FIXTURE` 只用于演示，结构回退不作为能力诊断。

评分层要求两遍评阅分别有原文引用；任一评分项证据缺失就阻止整次后验更新。兼容数字字段中的零贡献只是有依据的小计，不应解释成“未提到就是答错”。客户端辅助转写不能成为新事实基准。详见 [rubric-evaluator.ts](../app/lib/rubric-evaluator.ts)。

逐项展示同时检查可靠性、有限分数与原文引用：

| 条件 | 标签 | 含义 |
| --- | --- | --- |
| 可靠、有引用、分数 ≥3 | 已体现 | 本次回答体现该项，不代表跨场景掌握 |
| 同上、分数 ≥2 且 <3 | 部分体现 | 条件或说明仍需补充 |
| 同上、分数 <2 | 尚未充分体现 | 原话用于定位问题，有引用不代表判断正确 |
| 不可靠、无引用或无有效分数 | 无法判断 | 证据缺失，不列为已确认短板 |

待确认原因按现有字段区分转写、演示、语义评分未完成、评审分歧和证据不足；旧记录缺少故障字段时不能猜测故障类型。完整量表是参考清单；页面内补答草稿不保存、不评分、不覆盖原回答。

## 验证追问与历史兼容

只关联父题之后、同一来源且已被接受的可靠验证追问。父题移除 `__role_anchor` 包装，追问严格识别历史 `__verify_0` 与当前 `__verify_v3_0` 格式；不拿今天的题库覆盖旧记录的来源解释。

追问结论只支持其限定评分点，不升级为原题全项掌握；同源追问也不算独立多题支持。不同来源、先于父题、不可靠、畸形 ID 或仅标记 verification 的普通题都不能被关联。

## 训练建议与复测

训练重点优先对齐服务端实际可启动的推荐主题。首选主题无法组成完整题组时可尝试后续主题，但保留同主题、三道不同题、题族排除和无提示复测边界。没有完整题组时明确停止，不用无关题凑数。

复测仅比较完全相同的评分要求，并排除不可靠前测。先前证据有冲突则保留冲突；连续训练的对照采用来源训练的独立复测，不采用有提示练习。训练后验不是前后学习增益估计，单次分差不能推出长期效果。

## 验证证据与未完成事项

[报告回归](../tests/report-insights.test.ts)覆盖逐项状态、不同待确认原因、重复来源、旧/新题库与岗位基线追问、引用及复测冲突。[浏览器回归](../tests/browser-recovery.mjs)覆盖从报告进入三题训练和刷新后提示隐藏。测试使用合成数据，不能证明用户能理解反馈或模型判断正确。

真人评分仍为 `NOT_READY`：按[评分协议](SCORING_EVALUATION.md)先完成 48–72 条独立双标试点，再开展既有 200 条正式协议；训练试点另记录报告理解、训练/复测完成与失访，不临时更改冻结口径。语音与学习效果验证见[路线图](NEXT_STEPS_ZH.md)。
