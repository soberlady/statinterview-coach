# 个人面试训练闭环升级

更新：2026-10-03。版本：`coaching-v3`。本文件描述本地实现，不表示已部署到公开站点。

## 产品定位

StatInterview Coach 服务于中文数据分析岗位求职者的面试前训练：发现尚未掌握或尚未测清的知识点，提供练习，再用新场景检查能否独立应用。你用这个个人项目应聘 Agent 开发岗位，展示的是状态管理、受约束决策、可靠性控制、工具调用、检查点与评测能力。业务场景仍可保持数据分析，不必把题库改成 Agent 开发面试题。

当前结果不是录用建议，没有企业候选人排名、通过线或招聘效度结论。

2026-10-04 界面修正：移除前台 15 / 20 分钟选择，统一说明“7 道主问题、最多 2 次追问，可随时暂停并继续”。新诊断沿用内部默认预算 20；它只是选题成本参数，不承诺实际完成时间。接口仍接受原有预算字段，历史记录、策略回放和三题训练计划不变。

## 本次落地的变化

| 变化 | 当前行为 |
| --- | --- |
| 题库容量 | 从 24 扩到 48 道主问题，每个能力维度 12 道；共 97 条预置验证追问 |
| 内容组织 | 8 个知识点分组；每题标记题族、学习要点，每条追问有独立量表、难度及关联主问题标准 |
| 七题诊断 | 保留 2 道固定公共题、2 道冻结岗位定向题、3 道后验自适应题；全程最多另加 2 次验证追问 |
| 经历与难度 | 优先采用用户明确选择的熟悉程度；文本推断识别否定表达。后验阶段逐步让可靠回答表现影响目标难度 |
| 可靠性 | 清晰的错误回答可作为低分证据；短而完整的回答不再因字数被拒绝；无证据与答错分开处理 |
| 定向追问 | 按未覆盖或低分标准选择相关追问，使用追问自己的评分标准 |
| 能力覆盖 | 按已接受的可靠证据计算覆盖，不把仅仅问过当成已经测清 |
| 训练闭环 | 报告中启动两题有提示文本练习，再进行一题无提示复测；计划由服务端生成并持久化 |
| 复测排重 | 同一训练链避开已答原题，并保留未在来源会话及两道练习中出现的题族用于复测 |
| 结果解释 | 单独显示复测分数；本轮后验包含有提示练习，只作过程反馈，不直接与诊断后验比较 |
| 历史兼容 | 会话固定策略和题库版本；原 24 题与 v3 的 48 题各有不可变快照，评分和回放按版本读取 |
| 失败恢复 | 已保存回答可重复请求而不重复评分；最后一题结束确认失败时可重试或查看已保存报告 |
| 本机草稿 | 未提交文本按会话和题号保存，24 小时内可恢复；支持清除，提交确认后移除 |

训练优先使用可靠低分证据；没有明确薄弱证据时，优先补充缺少可靠证据的能力，再结合岗位权重与不确定性安排。证据不足明确标记为“补充观察”，不会写成“能力薄弱”。如果优先知识点没有完整未见题组，依次尝试其他合适主题并解释切换原因；所有候选都不足时才停止推荐。同一计划仍必须包含同主题的两道练习与一道未见题族复测。

48 题足够用于个人项目演示及少量训练轮次。它还不足以支撑长期高频训练；题族标记及新增内容尚需人工审题。排重仅沿同一条训练链传递，重新创建诊断或从同一报告重复创建分支可能重复题目。没有跨账号、跨设备的个人长期学习档案。

## 需要你参与的验收

1. **配置真实评分服务。** 按项目现有 `.env.example` 和运行文档在本机配置兼容服务，密钥只放本地配置。无配置时可验证界面、检查点及训练流程，但只提供结构反馈，不能形成可靠能力评分。
2. **审题。** 先审你最熟悉的一个维度，再请熟悉其他方向的人审剩余内容。重点看题意、量表是否能逐字取证、追问是否对准缺口、学习提示是否正确、复测题族是否确实不同。自动校验不等于内容正确。
3. **亲自完成一轮。** 填入真实 JD，完成七题诊断；从报告进入专项训练，回答一题后刷新或暂停恢复，确认继续同一道待答题；读完第二题反馈后进入复测，确认提示隐藏、报告复测结果独立展示。
4. **提交有针对性的反馈。** 特别试短而正确、明确错误、遗漏关键条件三种回答，记录会话 ID、题号、原回答、你期待的处理和实际处理。不要只反馈“分数不准”。
5. **再开展小规模真人 Pilot。** 先收集经同意、去标识化的 48–72 条回答，覆盖四个维度、不同水平及未提及/答错等边界，请第二位评阅者独立评分，用来修订量表和标注规范。之后再按既有评分协议冻结正式数据与测试集。

真人评分门禁仍是 `NOT_READY`；语音真实质量仍待测。Pilot、模型一致性、学习收益是不同问题，不能用合成测试或一次复测的高分替代真人效果结论。
