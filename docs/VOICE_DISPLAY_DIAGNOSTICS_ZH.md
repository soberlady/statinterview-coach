# 实时转写显示问题：排障与回归

## 已观察到的现象

一次私有语音测试中，浏览器后几轮的实时文字明显短于后台保存原文；用户核对后确认主要内容基本识别到了。该案例支持“显示同步滞后”的判断，但没有录音逐字对照，不能证明每个口语字词都被识别。

公开仓库只记录故障模式和合成测试，不包含私有报告地址、会话标识、原始回答或认证信息。

## 两条数据路径

`用户语音 → 语音服务 → 最终回答 → 后台保存 → 评分与报告`

`语音服务 → 浏览器转写流 → 实时文字 → 保存前的浏览器长度记录`

两条路径的进度可能不同。浏览器文字卡住，不能单独作为后台丢失答案的证据。

## 本地修复

1. 使用异步迭代逐段处理文本，不再等一个流关闭才刷新界面。
2. 在流到达时保留片段顺序；最终版本优先于临时版本，防止并发更新回退。
3. 回合保存后清空本题缓冲，拒绝仍在传输的旧回合、已见过的旧片段和旧连接回调。
4. 从下一题接口同步后台最近一轮原文，提供独立的“已保存转写”，方便核对结尾。
5. 在报告中按回合比较后台原文长度与保存前的浏览器缓冲长度，诊断事件不进入评分或选题。

这不是对底层网络停滞根因的证明。尚未见过的迟到片段缺少服务端回合标记，仍存在归属限制；自动测试也无法代替真人复测。

## 如何解读报告

| 结果 | 含义与下一步 |
| --- | --- |
| 长度一致 | 两份原始文本长度一致；仍需核对内容，不代表逐字一致或识别准确 |
| 实时文字较短 | 保存前浏览器记录比后台短；先检查已保存原文结尾，可能是显示滞后、空格差异或换题时序 |
| 实时文字较长 | 浏览器记录比后台长；核对原文及回合边界，不能直接判断后台截断 |
| 无法比较 | 缺少记录、旧版本、跳过多个回合、字段无效、记录互相冲突，或日志达到读取上限 |

后台轮数来自数据库完成的语音回答；浏览器保存检查点数量来自独立上报，二者不应混为一谈。

比较采用 JavaScript 原始字符串 UTF-16 长度，包含空格和标点；实时界面的百分比格式化不参与计数。新记录带 `transcriptBufferVersion: 2`。旧版缓冲可能残留上一题，因此历史记录不能回填为新版成功样本。达到报告事件读取上限时保守标为无法比较。

## 可复现验证

无需服务密钥，使用合成文本运行指定故障用例：

`npx tsx --test tests/voice-transcript-buffer.test.ts tests/voice-transcript-diagnostics.test.ts`

覆盖流未关闭前显示、并发完成顺序、临时片段晚到、换题、断线、长度差异、旧记录、无记录、冲突记录和日志上限。

`npm run test:e2e` 使用本地数据库和确定性评分替身，检查提交后原文保持完整、报告诊断正确，以及增加诊断事件前后能力状态和策略指纹不变。它不是线上模型质量测试。

## 部署后的真人验收

1. 在私有站新建一轮面试，其中一题连续回答 60–90 秒，并用自己容易记住的完整句子收尾。
2. 看实时文字是否逐段更新；换题后本题区域应清空。
3. 展开上一轮“已保存转写”，核对收尾句，再与报告原文对照。
4. 在报告查看“转写显示与保存核对”。记录发生问题的回合、现象及大致时间，不上传密钥或私人回答到公开仓库。
5. 若仍卡顿，提供私有报告链接继续核对。缺少事件应记为观测缺口，而不是成功样本。

## 面试讲解顺序

现象 → 对照两条数据路径 → 提出显示同步假设 → 修改流消费与回合隔离 → 加入失败路径回归 → 用报告持续观察 → 说明仍需真人验证的限制。

可重点解释：为何保留原始证据、为何缺失观测不等于零错误、为何诊断指标不能参与能力评分。这些是本项目可展示的工程判断；不要把本案例包装成已验证的生产级可靠性成果。
